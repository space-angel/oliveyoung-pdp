# 게이트1 동일성 — 옵션 정규화 결정 (PER-182)

PRD §4-1. "이 리뷰가 **정말 이 제품·이 옵션**에 대한 것인가."

구현은 `pipeline/option_norm.py`(정규화) · `pipeline/gates.py`(판정),
어휘는 `pipeline/option_markers.json`, 계약 테스트는 `pipeline/test_option_norm.py` ·
`pipeline/test_gates.py`. 수치의 1차 근거는
[`eval/reports/gate1_identity_per182.json`](../eval/reports/gate1_identity_per182.json)
이고 `.venv/bin/python eval/measure_gate1_identity.py` 로 재생성한다.

## 0. 결정 요약

| 무엇 | 결정 | 근거 |
|---|---|---|
| 제품 동일성 | 카탈로그가 정한 `productId` (PER-171) | 행의 `productKey` 문자열은 리뉴얼 세대를 못 가른다 |

## 1. 왜 옵션 정규화가 선행인가

스냅샷의 `option` 은 기재율 **68.1%**(17,016건)에 고유값 **798개**(제품별로 세어 합산)다.
그런데 798개가 798개의 색상을 뜻하지 않는다. 같은 색상이 판촉 포장만 달리해 흩어져 있다.

```
3CE 캐시미어 허그 립스틱 '허쉬 레드' — 실측 3형태, 합계 82건
  58  허쉬 레드(뉴트럴 베스트)
  17  [기획] 허쉬 레드+파우치
   7  [기획] 허쉬 레드+미니립스틱
```

정리하지 않으면 색상 질문의 근거가 색마다 잘게 쪼개져 충분성 하한(N_min=8, PER-186)을
넘지 못한다. 정규화의 실익은 여기서 측정된다 — **하한을 넘는 셀에 담긴 근거가
13,644건 → 14,212건(+568, +4.2%)** 이고, 셀 수는 369 → 252로 합쳐진다.
셀이 줄고 셀마다 커지는 것이 의도한 방향이다.

가장 크게 정리되는 제품:

| 제품 | 옵션 문자열 | → 색상 |
|---|---|---|
| 정샘물 에센셜 스킨 누더 쿠션 | 50 | 12 |
| 오프라 미니 하이라이터 | 43 | 14 |
| 에뛰드 컬 픽스 마스카라 | 35 | 8 |
| 데이지크 섀도우팔레트 | 47 | 28 |
| 헤라 블랙 쿠션 파운데이션 | 26 | 9 |

## 2. 방향이 다른 두 오류 — 규칙을 보수적으로 세운 이유

| 오류 | 결과 | 값 |
|---|---|---|
| 과소병합 | 같은 색이 안 합쳐진다 → 근거가 줄어 침묵한다 | 측정 가능한 손실 |
| 과대병합 | 다른 색이 합쳐진다 → **21호 근거가 13호 질문에 붙는다** | §7-1 치명 '잘못된 귀속' |

둘의 값이 다르므로 **모르면 가르는 쪽**을 기본값으로 뒀다. 못 알아본 괄호는 지우지 않고
식별자로 남긴다 — 지우는 쪽이 과대병합이기 때문이다.

```
닥터지 수딩크림   '70ml(튜브)+30ml(튜브)'  vs  '70ml(jar)+30ml(튜브)'
→ '(jar)' 를 못 알아봤으므로 지우지 않는다. 두 키로 갈린다
```

### 실제로 막은 과대병합 — 호수를 버리면 안 된다

이름만 키로 쓰면(호수를 버리면) 헤라 블랙 쿠션이 무너진다. 이름이 `N1` 로 같고
호수만 다르기 때문이다.

```
21N1 · 17N1 · 13N1 · 23N1 · 25N1 · 27N1  →  전부 'N1' (254건이 한 색으로 오병합)
```

그래서 **키에 호수를 남긴다.** 다만 같은 이름이 정확히 한 호수로만 나타나면 호수 없는
표기를 그 호수로 합친다(`로즈코티지` → `39|로즈코티지`). 호수가 둘 이상이면 합치지
않는다 — 그게 서로 다른 색이다. 실측에서 이 조건에 걸린 이름은 7개다.

## 3. 정규화 규칙 (전부 결정론적 · LLM 없음)

1. 괄호/대괄호 묶음을 떼어낸다
2. 묶음이 **판촉**이면 버린다 — `+` 로 시작(사은품)하거나, 판촉 토큰을 담고 있거나,
   용량·수량뿐인 경우
3. 살아남은 묶음도 **코퍼스가 판촉이라고 말하면** 버린다 (§4)
4. 남은 본문은 첫 `+` 조각만 쓴다 — `+` 뒤는 사은품이다
   (`글레이즈드 도넛 + 브러쉬 2ea` → `글레이즈드 도넛`)
5. 판촉 토큰·용량·구두점을 지우고 공백을 접는다
6. 남은 게 없으면 색상이 아니라 **용량/구성**(`pack`)이다
7. 앞머리 숫자를 호수로 떼고 `"{호수}|{이름}"` 을 키로 삼는다

### 공백을 접는 것은 여기서만이다

인용 대조(`tag_contract.fold_invisible`)는 공백 squeeze 를 **금지**한다 — 띄어쓰기를
지운 편집까지 인용으로 통과시키기 때문이다. 옵션은 인용이 아니라 **식별자**라서 반대
방향이 맞다. `03 베어그레이프` 와 `03 베어 그레이프` 를 가르면 같은 색이 쪼개진다.

### 판촉 어휘는 코드 상수가 아니다

`pipeline/option_markers.json` 에 관측 근거(문자열 수·리뷰 수)와 함께 둔다. 어휘를
늘리면 병합이 늘고, 잘못 늘리면 다른 색이 합쳐진다 — 그래서 토큰마다 근거를 붙인다.
가장 큰 토큰은 `기획`(252형태·6,487건), `리필`(80형태·1,902건), `본품`(65형태·1,268건)이다.

## 4. 코퍼스가 정하는 두 규칙 — 콜라보 이름을 목록으로 쫓지 않는다

판촉 어휘를 아무리 적어도 콜라보 이름(`[갸루키티]` · `[미피]` · `[망곰]` · `[태닝 포차코]`)은
끝이 없다. 목록을 늘려 잡는 대신 **그 묶음이 제품 안에서 식별자처럼 행동하는지**를 본다.

| 규칙 | 판정 | 예 |
|---|---|---|
| 래퍼-A | 한 묶음이 서로 다른 이름 2개 이상에 붙는다 → 색상과 직교하므로 판촉 | `[미피]` 는 40 베이지그레이프·02 누카다미아·03 베어그레이프에 붙는다 |
| 래퍼-B | 묶음을 떼면 **그 제품에 이미 있는 색상 이름**이 된다 → 같은 색의 포장 | `[갸루키티]30호 클래시누드블러링` → `30호 클래시누드블러링` 이 이미 있다 (141건 + 71건) |

두 규칙이 실제로 잡아낸 래퍼는 `갸루키티` · `미피` · `두유` · `조앤프렌즈` · `망그러진 곰` ·
`망곰` · `헬로키티` · `그린용기` · `틴케이스` · `코랄` · `리뉴얼` · `HOT` 등이다.
반대로 `쿄카 PICK` · `스노우` · `포도` · `살구` · `튜브` · `jar` · `전용퍼프` 는 어느 규칙에도
걸리지 않아 **식별자로 남았다.**

용량·수량뿐인 묶음(`(8구)` · `(12g)`)은 판촉으로 본다. 그래서
`팔레트 케이스(8구)` · `(4구)` · `(3구)` 는 한 키로 합쳐진다. **색상 병합이 아니라 구성
병합이라 잘못된 귀속을 만들지 않는다** — 색상 질문이 구성을 범위로 걸 수 없기 때문이다
(§6의 `resolve_scope` 가 에러를 낸다).

## 5. 옵션 컷은 질문이 요구할 때만 건다

옵션은 조건축이지 항상 거는 컷이 아니다. "지속력 어때요"에 색상 컷을 걸면 기재분만
남고 나머지 31.9%가 이유 없이 사라진다. 그래서 **호출부가 `IdentityScope.option_key` 를
채울 때만** 건다 — 그게 §4-1 의 "색상·호수 질문이면"이다.

범위를 걸면 비용이 크다. 제품마다 가장 큰 색상 1개를 범위로 잡아 실측했다.

```
대상 14,000건 (색상축이 관측된 제품 31개)
  통과          4,776
  옵션불일치    7,827
  기간초과      1,102
  옵션미기재      295
```

| 제품 | 범위 | 통과 / 전체 |
|---|---|---|
| 정샘물 에센셜 스킨 누더 쿠션 | `페어라이트` | 120 / 500 |
| 헤라 블랙 쿠션 파운데이션 | `21\|N1` | 92 / 341 |
| 롬앤 더 쥬시 래스팅 틴트 | `3\|베어그레이프` | 114 / 500 |

**옵션미기재를 불일치와 따로 세는 것이 요점이다.** 둘을 한 사유로 뭉치면 "색상을 안
적어서 못 쓴 근거"와 "다른 색이라 못 쓴 근거"를 구분할 수 없고, 옵션 정규화를 개선했을 때
무엇이 좋아졌는지 귀속되지 않는다.

---

## 6. 모르면 멈춘다 — 조용한 폴백 금지

질문의 옵션 범위는 리뷰와 **같은 정규화**를 거쳐야 비교가 대칭이다
(`OptionIndex.resolve_scope()`). 그 제품에서 관측되지 않은 색상이면
`UnknownOptionScopeError` 다.

임의로 통과시키면 존재하지 않는 색상에 근거가 붙고, 임의로 전부 탈락시키면 질문이 조용히
침묵한다. 어느 쪽도 자동으로 고르지 않는다. 이 에러는 색상축이 없는 제품(크림·세럼)에
색상 범위를 거는 사고도 같이 막는다.

## 7. 컷 비용 (옵션 범위 없음 · 기본 경로)

```
리뷰 25,000건
  통과        22,194
  기간초과     2,806   (11.2%)  리센시 컷 — 2024-09 ~ 2026-08
  리뉴얼이전       0
```

리뉴얼 컷의 실효는 **0**이다. 카탈로그의 `renewalPolicy` 는 `unobserved` 45 · `separate` 6 ·
`single` 2 인데, `separate` 6개는 세대가 `goodsNo` 로 이미 갈려 있어(양쪽 구간이 열림)
날짜 컷이 걸리지 않는다. 이건 컷이 고장 난 게 아니라 **관측 범위의 사실**이고,
`unobserved` 제품의 통과분에는 `renewal_unobserved` 한계가 따라붙는다 (45개 제품).

## 8. 남는 한계 — 숨기지 않는다

1. **`hasShadeAxis` 는 "옵션 열이 갈린다"는 뜻이지 "색상이 있다"는 뜻이 아니다.**
   메이크업 28개 중 27개가 참인 반면 스킨케어 16개 중 4개도 참으로 나오는데, 그건
   색상이 아니라 용기·구성이 갈리는 경우다(`(튜브)`/`(jar)`). 이 값을 색상 유무의
   정본으로 쓰면 안 된다. 실질 보호는 `resolve_scope` 의 에러다.
2. **과대병합이 0이라고 선언하지 않았다.** §2의 회귀 사례를 테스트로 고정했을 뿐이다.
   리포트에 색상 키별 원본 문자열(`mergedForms`, 병합된 키 129개)과 이름이 포함관계인
   키 쌍(`containmentPairs`)을 실어 사람이 훑어볼 수 있게 남겼다.
3. **남은 과소병합이 있다.** 바로 위 두 규칙에 걸리지 않는 사은품 표기가 남는다
   (예: 퓌 3D 볼류밍 글로스의 `소르베70`(9건)과 `바닐라소르베70`(131건)). 방향이
   침묵 쪽이라 잘못된 귀속을 만들지 않는다.
4. **옵션 정규화는 색상만 정리한다.** 용량·구성(`pack` 2,157건)은 한 덩어리로 두고
   가르지 않는다. 60ml 와 60+60ml 의 차이가 크림의 주장을 무효화하지 않기 때문이다.
