# 04 — 성공 기준

## 1차 합격선 (Gate): 구조 검증

파이프라인이 완료되면 자동 검증 스크립트(`eval/check_structure.py`)로 확인.
**아래 조건을 모두 통과해야 EVAL 단계로 진입 가능.**

| 항목 | 기준 | 측정 방법 |
|---|---|---|
| 제품 커버리지 | 5개 제품 모두 결과 존재 | `len(products) == 5` |
| 질문 수 범위 | 제품당 3~7개 질문 | 모든 제품 `3 ≤ len(concerns) ≤ 7` |
| 최소 근거 리뷰 | 질문당 근거 리뷰 ≥5건 | `len(supportingReviewIds) >= 5` |
| 유효한 reviewId | 근거 ID가 입력 데이터에 존재 | ID 교차 검증 |
| 의문형 질문 | 질문이 `?`로 종결 | `question.endswith('?')` |
| 카테고리 유효값 | 4개 카테고리 중 하나 | enum 검증 |

## 2차 평가 (Quality): 질문 품질

EVAL이 아래 두 지표를 concerns.json 전체에 대해 측정한다.

### 지표 1 — 구체성 지수 (Specificity)

**정의**: 질문이 해당 제품의 특정 속성을 명확히 지목하는가?

| 점수 | 기준 | 예시 |
|---|---|---|
| 2 | 특정 측면 + 사용 맥락 포함 | "복합성 피부에 T존 유분 없이 하루 종일 유지되나요?" |
| 1 | 특정 측면만 언급 | "민감한 피부에 트러블이 생기나요?" |
| 0 | 일반적이거나 모호함 | "이 제품이 좋은가요?" |

**목표**: 평균 ≥ 1.3점 (전체 질문 기준)

### 지표 2 — 리뷰-질문 적합도 (Relevance)

**정의**: `supportingReviewIds`의 리뷰들이 실제로 해당 질문에 답을 주는가?

| 점수 | 기준 |
|---|---|
| 5 | 근거 리뷰의 80% 이상이 질문에 직접 답변 |
| 4 | 60~80% 답변 |
| 3 | 40~60% 답변 |
| 2 | 20~40% 답변 |
| 1 | 20% 미만 — 질문과 리뷰가 무관 |

**목표**: 평균 ≥ 3.5점 (전체 질문 기준)

---

## 3차 검증 (Coverage): 감성 다양성

구매 고민은 긍정/부정이 공존해야 의미 있다.

| 항목 | 기준 |
|---|---|
| 감성 혼재 질문 비율 | 제품당 ≥1개 질문이 `positiveCount ≥ 2` AND `negativeCount ≥ 2` |
| 카테고리 분포 | 제품당 4개 카테고리 중 ≥3개 커버 |
| 리스크 질문 존재 | 5개 제품 중 ≥4개에 `category=리스크` 질문 1개 이상 |

## Golden Set 기준

EVAL이 human evaluation을 위한 golden set을 구성할 때 사용할 선정 기준:

**포함 기준** (아래 조건을 모두 충족):
1. 실제 구매자가 검색창이나 Q&A에 입력할 법한 질문
2. 제품 상세설명만 읽어서는 답을 알 수 없는 질문 (리뷰에서만 답이 나오는 것)
3. 5건 이상의 리뷰가 직접적인 답변을 제공

**제외 기준**:
- 제품 설명에 이미 나와 있는 정보 (예: "EWG 녹색 등급인가요?")
- 리뷰가 아닌 외부 정보로 답해야 하는 것 (예: "이 제품 성분 분석해줘")
- 특정 1~2명 리뷰어의 극단적 경험에만 근거한 질문

**Golden Set 크기**: 제품당 3~5개 질문, 총 15~20개

## 평가 기준 요약

| 단계 | 기준 | 합격선 |
|---|---|---|
| Gate (구조) | 자동 검증 | 전항목 Pass |
| Quality (구체성) | 평균 Specificity | ≥ 1.3 / 2.0 |
| Quality (적합도) | 평균 Relevance | ≥ 3.5 / 5.0 |
| Coverage (감성) | 혼재 질문 비율 | 제품당 ≥1개 |
| Coverage (카테고리) | 분포 | 제품당 ≥3/4 카테고리 |

**v4 종합 합격**: Gate 통과 + Specificity ≥ 1.3 + Relevance ≥ 3.5
