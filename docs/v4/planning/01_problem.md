# 01 — 문제 정의

## 해결하려는 문제

올리브영 PDP에서 소비자는 구매 결정을 위해 수백 개의 리뷰를 직접 읽어야 한다.
리뷰가 많을수록 오히려 "내 상황에 맞는 정보"를 찾기 어려워지는 역설이 발생한다.

## 사용자 페인포인트

### 1. 정보 과부하
- 제품당 100건 이상의 리뷰, 평균 길이 213자
- 83.8%(419/500건)가 별 5개 — 긍정 일색이라 부정 신호를 찾으려면 전체를 훑어야 함
- "좋아요 6,534개"를 받은 리뷰가 별 1개 경고(피부 트러블) — 리스크 정보는 묻혀 있음

### 2. 피부 타입 필터 부재
- 데이터 확인 결과: `skinType`, `skinTone`, `skinConcerns` 필드 **전체 500건이 공란**
- 구조화된 필터 없이 "복합성 피부에도 괜찮나요?" 같은 질문은 텍스트를 직접 읽어야만 답이 나옴
- 같은 제품, 피부 타입별로 경험이 극명히 갈리는 경우가 많음 (달바 세럼: 건성 호평 / 민감성 트러블)

### 3. 의견 충돌 파악 불가
- "제품이 트러블 날 수 있다"는 사실은 긍정 리뷰 속에 희석됨
- 어떤 측면에서 의견이 갈리는지 한눈에 알 수 없음

## 목표 결과물이 해결할 것

**"구매 고민 질문"**: 소비자가 구매 전에 실제로 던질 법한 질문을 리뷰 기반으로 자동 생성한다.

예시:
- "민감한 피부도 자극 없이 쓸 수 있나요?" (리스크)
- "복합성 피부에서 T존 유분이 생기지 않나요?" (적합성)
- "메이크업 위에 뿌려도 뭉치지 않나요?" (실사용)

각 질문에는 리뷰 근거(긍정/부정 증거)와 함께 제공되어, 사용자가 리뷰를 읽지 않고도 핵심 판단을 할 수 있게 한다.

## 비즈니스 맥락

| 목표 | 설명 |
|---|---|
| 전환율 향상 | 구매 불확실성 제거 → 결제까지 이탈 감소 |
| 반품 감소 | 리스크 정보를 사전에 제공 → "나한테 맞을지" 판단 지원 |
| UGC 활용 | 리뷰의 잠재 정보량을 실제 가치로 전환 |

## 핵심 제약 (DEV에게)

- **피부 타입 메타데이터 없음**: 모든 피부 타입 정보는 리뷰 텍스트에서 직접 추출해야 함
- **카테고리 혼재**: 스킨케어(세럼/크림)와 색조(쿠션/틴트)의 구매 고민 유형이 다름 — 제품 카테고리 인식이 필요
- **긍정 편향**: 별 5개가 83.8% — 부정 신호는 희소하지만 구매 결정에 매우 중요
