# DEV 피드백 — Step 1 aspect를 enum으로 고정 (누수 차단)

> 출처: PoC 콘솔 테스트 (리뷰 3건) 후 발견. 우선순위 높음.

## 발견한 문제

Step 1 콘솔 테스트에서 LLM이 뽑은 aspect 8개 중 3개(`사계절 사용성`, `피부 적합성`, `피부 표현력`)가
Step 2 `SYNONYM_MAP`에 매핑되지 않았다.

`normalize_aspect()`는 매핑 실패 시 **자유 텍스트를 그대로 유지** → `MIN_SUPPORT=5`에 걸려 **조용히 버려진다.**
정확히 같은 자유 텍스트가 5번 이상 반복돼야 살아남는 구조라, 이는 v4가 없애려던 **v3식 자유 텍스트 집계의 취약성**과 동일하다.

특히 `피부 적합성`은 PM 4축 중 1번(적합성)에 해당하는 핵심 신호인데 증발할 위험.

## 해결 방향: 출력(Step2)이 아니라 입력(Step1)에서 막는다

LLM이 애초에 **닫힌 enum 14종 중에서만** aspect를 고르게 한다.
→ taxonomy 밖 표현이 안 나옴 → Step 2 매핑 누수 0.
→ 의미 분류는 LLM이 수행("꾸덕하게 보습"→`보습감`), 우리는 칸만 고정.

## layer 분리 (중요)

- **aspect (Step 1 enum, 아래 14종)**: "무엇에 대한 말인지". 닫힌 집합.
- **category/4축 (Step 3)**: "어떤 구매 고민 유형인지" (적합성/리스크/실사용/비교).
- `적합성` 축은 별도 aspect가 아니다. `skinTypeHint` + aspect 조합으로 Step 3에서 판정.
  (예: `보습감` + `skinTypeHint=건성` → 적합성 concern)

## 확정 aspect enum (14종)

```
보습감
흡수력
발림감/텍스처
지속성
향
광택/윤기
커버력
발색
유분/번들거림
트러블/자극
탄력/탱탱함
분사력
밀착력
가성비
```

> 제품군(5종)에 따라 일부 aspect는 안 나올 수 있음(예: 분사력=스프레이 전용). enum은 superset이면 됨.
> `재구매`는 입력에 `isRepurchase` 필드가 이미 있으므로 aspect에서 제외.
> `보관/용기`, `사용감`은 구매 고민 신호가 약해 제외.

## 해야 할 작업

### 1. `prompts/step1/v1.md` 수정
- 추출 규칙 2번을 "aspect는 **반드시 아래 14종 중 하나**"로 변경하고 enum 목록을 박는다.
- **어느 칸에도 맞지 않으면 그 claim을 생략**한다(억지로 욱여넣지 말 것). 기존 "불확실하면 제외" 규칙과 일관.
- 출력 예시의 aspect도 enum 값으로 교체.

### 2. `pipeline/step2_aggregate.py` 정리
- 이제 Step 1이 canonical만 내보내므로 `SYNONYM_MAP`은 **안전망(혹시 enum 외 값이 오면 흡수)** 역할로 축소하거나, enum 14종을 그대로 키로 사용.
- enum 외 값이 들어오면 버리지 말고 **로그로 경고** 출력 (프롬프트 이탈 모니터링용).

### 3. 검증
- 같은 리뷰 3건으로 Step 1 재실행 → 8개 aspect가 전부 enum 14종 안에 들어오는지 확인.
- 특히 `피부 적합성`이 사라지고, 그 신호가 `skinTypeHint`로 보존되는지 확인.

- 500건 전체 실행 시 "enum 외 값" 경고 로그 비율 < 5%
