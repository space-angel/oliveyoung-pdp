# AI 9개에게 같은 시험지를 줬어요

**리뷰를 표로 바꾸는 일에 어떤 모델이 맞는지, 짐작 대신 재본 이야기**

2026-09-15 · 올리브영 PDP 리뷰 파이프라인 · 근거는 전부 `eval/reports/v5_tag_bedrock_bakeoff.md` 에 있어요

---

## 먼저, 무슨 일을 시키는 건가요

저희는 리뷰 25,000개를 읽고 **"건성인데 속당김 없나요?"** 같은 질문에 답하는 걸 만들고 있어요. 답하려면 "건성이라고 밝힌 12명 중 9명이 괜찮다고 했어요" 처럼 **셀 수 있어야** 해요.

그런데 리뷰는 줄글이에요. 그래서 먼저 표로 바꿔둬요.

> "한달정도 사용해봤는데 순하고 촉촉하네요. 속보습이 된다고 써 있는데 전 건성이라 그런지 **속보습은 못 느꼈어요**. 펴바르고 나면 **금새 날라가는 느낌이에요**."

| 리뷰 | 주제 | 방향 | 근거 문장 |
|---|---|---|---|
| 4119503 | 보습감 | 부정 | "속보습은 못 느꼈어요" |
| 4119503 | 지속성 | 부정 | "금새 날라가는 느낌이에요" |

이 표 만들기를 **태깅**이라고 불러요. 이걸 AI에게 시키는데, 규칙이 세 개 있어요.

1. **주제는 정해진 14개 중에서만** 골라요 (보습감·흡수력·발색·지속성·향·가성비…). 없는 칸을 만들면 나중에 집계가 안 돼요
2. **한 리뷰에 같은 주제를 두 번 쓰면 안 돼요.** 같은 사람이 같은 주제에 찬반 양표를 던지는 셈이라 방향이 흐려져요
3. **근거 문장은 리뷰에서 그대로 잘라낸 것**이어야 해요. 요약도, 맞춤법 교정도 안 돼요

3번이 제일 빡빡한데, 이유가 있어요. 이전 버전에서 인용 원문 일치율이 88.8%였고, 나머지에서 **원문에 없는 수치를 만들어낸 사례**가 있었거든요. 그래서 지금은 규칙을 어긴 태그를 **버려요.**

## 채점표 읽는 법

사람이 만든 정답지가 있어요. 리뷰 200건에 태그 **432개**. 모델이 낸 것과 이 정답지를 맞춰봐요.

### 지표 1. 정밀도 — "낸 것 중에 맞은 게 얼마나 되나"

모델이 태그 100개를 냈는데 그중 84개가 정답지에도 있으면 정밀도 84%예요.

**낮으면 = 없는 말을 지어내요.** 리뷰가 향 얘기를 안 했는데 향 태그를 붙이는 거죠. 저희한테 제일 위험한 실패예요. 사용자가 "12명이 좋다고 했어요"를 읽었는데 그중 3명은 그런 말을 한 적이 없는 거니까요.

### 지표 2. 재현율 — "있는 것 중에 얼마나 찾았나"

정답지에 432개가 있는데 모델이 그중 214개를 찾았으면 재현율 49.5%예요.

**낮으면 = 놓쳐요.** 리뷰가 분명히 말했는데 모델이 못 보고 지나간 거예요. 이건 덜 위험하지만, 놓친 만큼 **답할 수 있는 질문이 줄어들어요.**

### 왜 둘을 같이 봐야 하나요

하나만 보면 속아요. 극단적으로,

- **태그를 딱 1개만 내고 그게 맞으면 정밀도 100%예요.** 그런데 431개를 놓쳤죠
- **모든 리뷰에 14개 주제를 다 붙이면 재현율이 확 올라가요.** 대신 대부분이 헛소리예요

그래서 둘을 같이 봐요. 그리고 저희는 **정밀도 쪽에 더 무게를 둬요** — "덜 보여주고 틀리지 않기"가 이 시스템의 기울기거든요. 놓친 질문은 사용자가 리뷰를 직접 읽으면 되지만, 틀린 확신은 되돌릴 수 없어요.

### 지표 3. 방향 일치 — "긍정/부정을 맞게 붙였나"

주제를 맞게 찾았어도 방향이 반대면 최악이에요. "지속력 별로"를 긍정으로 읽으면 안 사야 할 사람이 사게 돼요.

### 그리고 지표 밖의 두 가지

점수표에 안 나오지만 더 중요한 게 둘 있어요.

**규칙 위반 수.** 위 규칙 1~3을 어긴 태그예요. 이건 **점수를 깎는 게 아니라 버려져요.** 모델이 아무리 좋은 태그를 냈어도 인용을 한 글자 고쳤으면 그 태그는 없어져요. 돈은 냈는데 못 쓰는 거죠.

**리뷰 수거율.** 200건을 줬는데 몇 건을 읽고 왔나예요. 이게 **제일 무서운 지표**인데, 뒤에서 이야기할게요.

## 시험을 공정하게 만드는 게 제일 어려웠어요

9개 모델을 비교하려면 **조건이 하나도 달라선 안 돼요.** 같은 리뷰 200건, 같은 지시문, 한 번에 주는 리뷰 개수(20개)까지 똑같이. 하나라도 다르면 "이 모델이 더 좋다"가 아니라 "이 설정이 더 좋다"가 되거든요.

이게 말처럼 쉽지 않았어요. 어떤 모델은 20개를 주면 버거워하는 게 눈에 보였는데, **그래도 20개로 고정했어요.** 그게 실제 운영 설정이고, 버거워한다는 사실 자체가 결과니까요. 배려해서 5개씩 주면 그건 다른 시험이에요.

## 모델마다 "틀리는 방식"이 달라요

규칙을 어겨서 버려진 태그들을 유형별로 갈라봤어요. 성격이 보여요.

| 모델 | 버려진 태그 | 제일 많은 실패 |
|---|---:|---|
| Kimi K2.5 | 28 / 375 | **같은 주제 두 번 (22건)** |
| MiniMax M2.5 | 27 / 345 | **인용을 고침 (23건)** |
| Qwen3 Next | 41 / 379 | **없는 주제를 만듦 (14건)** |
| GLM 4.7 Flash | 35 / 341 | 인용을 고침 (20건) |
| GLM 4.7 | 13 / 305 | 고르게 조금씩 |
| gpt-oss 120B | 4 / 238 | 인용을 고침 (4건) |

### Kimi는 부지런한데 결정을 못 해요

Kimi는 태그를 제일 많이 찾아요(재현율 66.2, 1등). 그런데 버려진 28건 중 **22건이 "같은 주제 두 번"**이에요.

```
리뷰 37635624   발색 / 긍정
                발색 / 부정    ← 같은 리뷰, 같은 주제, 반대 방향
```

리뷰가 "발색은 예쁜데 시간 지나면 칙칙해져요" 같은 말을 했을 때, 규칙은 **"발색 긍정 + 지속성 부정으로 나누되, 나눌 수 없으면 만들지 마라"**예요. Kimi는 나누지도 않고 포기하지도 않고 **둘 다 냈어요.** 판단을 미룬 거죠.

### MiniMax는 자꾸 문장을 다듬어요

MiniMax가 버린 27건 중 **23건이 인용 변조**예요. 원문을 그대로 안 가져와요.

```
원문    흡수도 빠른편이네요
MiniMax  흡수가 빠른편이네요     ← 조사를 바꿨어요
```

한 글자예요. 그런데 이게 왜 문제냐면, 저희는 이 문장을 **화면에 그대로 띄우거든요.** "리뷰에서 가져온 문장"이라고 하면서 실제로는 AI가 손본 문장이면, 그건 인용이 아니에요.

### 그런데 인용 실패가 다 모델 탓은 아니에요

같은 문장에서 GLM 4.7과 Kimi가 나란히 떨어진 사례가 있어요.

```
원문      눈시림⏎이었는데 저는 전혀 없었어요     ← 리뷰어가 여기서 줄을 바꿨어요
GLM      눈시림 이었는데 저는 전혀 없었어요      ← 줄바꿈을 띄어쓰기로
Kimi     눈시림이었는데 저는 전혀 없었어요       ← 줄바꿈을 아예 없앰
```

리뷰어가 문장 한가운데서 엔터를 쳤어요. 사람 눈엔 안 보이는 글자죠. 모델이 옮겨 적으면서 이걸 흘렸는데, **이건 의미를 바꾼 게 아니에요.**

이런 건 저희가 코드로 되돌릴 수 있어요 — 원문에서 그 자리를 찾아 **원문 그대로의 문자열로 바꿔치기**하면 돼요. 대조 기준을 무르게 하는 게 아니라, 저장되는 값을 원문으로 되돌리는 거예요. 참고로 저희 리뷰 25,000건 중 **46.3%**에 이런 줄바꿈이 섞여 있어요. 무시할 양이 아니에요.

단, MiniMax의 `흡수도 → 흡수가`는 **되돌릴 수 없어요.** 글자가 달라졌으니까요. "줄바꿈만 복원하고 글자가 다르면 손대지 않는다"가 경계선이에요. 이 선을 넘으면 오타 교정과 **숫자 날조**를 같이 통과시키게 되거든요.

### Qwen은 양식 자체를 헷갈려요

Qwen이 버린 41건 중 **14건이 "목록에 없는 주제"**인데, 뜯어보면 둘로 갈려요.

**7건은 `skinTypeHint`를 주제 칸에 적었어요.** 이건 주제 이름이 아니라 **양식의 칸 이름**이에요. 이름·주소·연락처를 적는 서류에서 "연락처" 칸에 `연락처`라고 적은 셈이죠. 개념을 지어낸 게 아니라 서류를 잘못 읽은 거예요.

나머지 7건이 진짜로 없는 개념이었어요 — `효능`(2), `포장/디자인`(3), `수분감`, `모공`.

재현율은 58.3으로 나쁘지 않은데 정밀도가 74.6으로 제일 낮아요. **많이 내고 많이 틀려요.**

### GLM 4.7은 조용하고 정확해요

GLM 4.7은 태그를 305개로 중간쯤 내는데, 버려진 게 13개뿐이에요. 특정 실패에 몰려 있지도 않아요. 그리고 **출력이 제일 짧아요** — 리뷰 하나당 84토큰. 군더더기 없이 표만 내고 끝내요.

## 제일 이상했던 발견: 생각할 시간을 줄이면 오타를 고쳐요

요즘 모델 중에는 답하기 전에 **혼자 생각하는** 종류가 있어요. 그 생각의 양을 조절할 수 있는데, 같은 모델·같은 리뷰로 이걸 바꿔봤어요.

원문에 오타가 있는 리뷰예요. "몇번을 **ㅁ**써도 익숙해 지지가 않네요" — `ㅁ`이 잘못 들어갔죠.

```
생각 많이 (기본)  →  "향.. 몇번을 ㅁ써도 익숙해 지지가 않네요"   ← 오타 그대로 ✅
생각 적게 (low)   →  "향.. 몇번을 써도 익숙해 지지가 않네요"     ← 오타를 지웠어요 ❌
```

생각할 여유가 없으면 **"이건 오타니까 고쳐주자"** 쪽으로 기울어요. 친절한 행동인데, 저희 규칙에선 그 태그가 통째로 버려져요.

이게 왜 중요하냐면, 저희는 처음에 이걸 **지시문 문제**로 봤거든요. "오타를 고치지 마라"고 더 세게 써야 하나 고민했어요. 재보니까 **지시문이 아니라 생각 예산 문제**였어요. 원인을 잘못 짚었으면 안 듣는 문장을 계속 다듬고 있었을 거예요.

## gpt-oss 이야기: 생각하다가 시간이 끝났어요

표에서 유일하게 **리뷰를 다 못 읽은** 모델이 둘 있어요. gpt-oss 120B는 180/200, 20B는 **120/200**이에요. 200건을 줬는데 80건은 읽지도 못하고 온 거예요.

무슨 일이 있었냐면.

모델에게 한 번에 쓸 수 있는 출력 분량이 정해져 있어요. gpt-oss 계열은 답하기 전에 생각을 아주 많이 하는 모델인데, **그 생각도 출력 분량에 포함돼요.** 리뷰 20개짜리 한 묶음에서 실제로 측정해보니,

```
생각한 내용    11,312자
실제 답(표)     1,285자     ← 전체의 11%
```

**출력의 89%가 생각이었어요.** 그러다 분량을 다 쓰면 답을 쓰다 말고 잘려요. 잘린 답은 읽을 수 없으니 그 묶음 20건이 통째로 사라져요. 20B에선 이게 4번 일어나서 80건이 없어진 거예요.

리뷰 하나당 출력이 337토큰인데, 같은 일을 GLM 4.7은 84토큰으로 해요. **4배를 쓰고 결과는 더 적게 가져오는** 셈이에요.

교훈이 하나 있어요. **"똑똑한 모델"과 "이 일에 맞는 모델"은 달라요.** 리뷰에서 문장을 뽑아내는 건 깊이 고민할 일이 아니라 꼼꼼히 훑을 일이에요. 생각을 많이 하는 모델은 여기서 장점이 그대로 단점이 돼요.

## 모델 네 개가 같은 칸을 만들어내려 했어요

아까 Qwen이 "없는 주제를 지어낸다"고 했죠. 그런데 어떤 주제를 지어냈는지 모아보니 좀 놀라웠어요.

지어낸 것들이 두 종류로 갈려요.

**하나는 그냥 이름을 틀리게 쓴 거예요.** `발림성/텍스처`(원래는 `발림감/텍스처`), `자극/트러블`(원래는 `트러블/자극`), `보습력`·`수분감`(원래는 `보습감`) 같은 것들요. 이건 새 개념이 아니라 받아쓰기 실수예요.

**나머지가 흥미로워요. 우리 목록에 정말로 없는 개념이에요.**

```
모공 · 모공관리       2회   (Qwen, Kimi)
포장/디자인 · 패키지   4회   (Qwen 3, GLM Flash 1)
효능                2회   (Qwen)
```

서로 다른 회사의 모델들이 **같은 칸을 원했어요.**

그리고 이건 저희도 이미 알고 있던 구멍이에요. 사람이 정답지를 만들 때도 태그를 하나도 못 붙인 리뷰가 12건 있었는데, 그중 절반이 **"칸이 없어서"**였거든요 — 모공, 주름, 톤 적합성, 용기 불량, 휴대성.

> "모공관리할려고 추천받고 써봤는데 생각보다 괜찮아요"
> "틴트가 산지 하루만에 세요, 결합 불량"

두 번째 리뷰는 별점 1점이에요. **사면 안 되는 이유를 말하고 있는데 저희 표에 들어갈 칸이 없어요.**

그래서 주제 목록을 넓히기로 이미 정해뒀어요. 다만 **지금은 아니에요** — 정답지가 14개 주제 기준으로 만들어져 있어서, 지금 칸을 늘리면 채점 기준이 무너지고 이전 버전과의 비교도 못 하게 되거든요. 순서가 있어요.

재밌는 건, 모델들이 규칙을 어긴 게 **우리 설계의 빈 곳을 가리키고 있었다**는 거예요. 위반 기록을 버리지 않고 남겨둔 덕에 보였어요.

---

## 하마터면 틀린 표를 낼 뻔했어요

솔직한 이야기 하나요.

실험을 자동으로 돌리는 스크립트에서 **두 모델이 같은 이름표를 받았어요.** MiniMax `M2.5`와 Kimi `K2.5` — 이름 끝이 같아서 프로그램이 둘을 같은 실험으로 착각했어요.

저희 도구엔 "중간에 끊기면 이어서 하기" 기능이 있어요. 그래서 Kimi 차례가 왔을 때, 프로그램은 **"이 실험은 이미 끝났네"** 하고 AI를 한 번도 부르지 않았어요. 그리고 **MiniMax가 만든 태그를 Kimi의 성적표로 채점했어요.**

결과 파일엔 `모델: Kimi`라고 적혔는데 내용물은 MiniMax였어요. 표만 봤으면 몰랐을 거예요.

다행히 로그를 훑다가 **"남은 작업 0개"**라는 줄이 눈에 걸렸어요. 처음 돌리는 모델인데 남은 게 없다는 건 말이 안 되니까요.

고친 방법은 이래요. 이어서 하기 전에 **"이 실험이 정말 같은 실험인지"** 확인해요 — 모델 이름, 지시문, 입력 데이터가 전부 같아야 이어서 하고, 하나라도 다르면 멈춰요.

이런 종류의 사고가 제일 무서워요. 에러가 안 나거든요. 그냥 **조용히 틀린 숫자**가 나와요.

## 그래서 뭘 골랐나요

**GLM 4.7**이에요.

- 정밀도 88.0으로 **전체 1등**. 저희가 제일 중요하게 보는 지표예요
- 재현율 59.5로 기존 최고(Sonnet 5, 55.8)보다 높아요
- 200건을 다 읽었고, 잘린 묶음이 없어요
- 25,000건에 $3.84. 기존 후보였던 Haiku 4.5($8.38)의 절반이에요

Kimi가 재현율은 66.2로 더 높은데 **정밀도가 82.4로 Haiku(84.3)보다 낮아요.** 더 많이 찾아오지만 그중 틀린 게 더 많다는 뜻이에요. "덜 보여주고 틀리지 않기"라는 기준에선 안 맞아요.

다만 Kimi의 실패가 **22건이 "같은 주제 두 번"**이었던 게 걸려요. 이건 저희가 코드로 정리할 수 있는 종류예요("방향이 갈리면 둘 다 버린다"는 규칙이 이미 있는데 아직 구현을 안 했어요). 그걸 넣고 다시 재면 순위가 바뀔 수도 있어요.

## 아직 모르는 것

- **정답지 200건짜리예요.** 사람이 만든 정답지의 품질이 재현율의 천장이에요. 100%는 의미 없는 목표고, 정답지에 없는 태그 중에도 진짜가 섞여 있어요
- **정답지를 만든 것도 AI(Claude Opus 5)예요.** 사람이 검수했지만, 특정 모델을 여기 맞춰 올린다는 건 "정확해진다"가 아니라 "그 모델을 닮는다"는 뜻일 수 있어요
- **주제 목록을 넓히면 다시 재야 해요.** 모델들이 원했던 모공·용기 칸이 생기면 지금 순위가 그대로일 거란 보장이 없어요
- **한 번 재본 거예요.** 같은 조건에서 여러 번 돌려 흔들림을 보진 않았어요
