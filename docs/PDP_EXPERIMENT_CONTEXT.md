# PDP 실험 컨텍스트 핸드오프

> 이 문서는 올리브영 리뷰 분석 파이프라인 팀 → PDP 구현 팀으로 넘기는 실험 설계 컨텍스트입니다.

---

## 1. 우리가 만든 것 (파이프라인 결과물)

올리브영 리뷰를 LLM으로 분석해 **"구매 고민 질문 + 대표 리뷰 답변"** 구조를 자동 생성하는 파이프라인을 구축했습니다.

```
크롤링 → contextTag 추출 → 태그 클러스터링 → 고민 질문 생성
```

**핵심 아이디어:**  
구매자가 제품을 살지 말지 고민할 때 실제로 궁금해하는 질문을 리뷰에서 역으로 추출하고,  
그 질문에 답하는 대표 리뷰 문장(quote)을 함께 제공합니다.

---

## 2. 데이터 파일 위치

```
oliveyoung-crawler/data/
├── reviews_200.json       # 5개 제품 × 최대 200건 크롤링 리뷰 (총 500건)
├── concerns_v2.json       # 파이프라인 최종 출력 — 제품별 고민 Q&A
├── merged_tags.json       # 중간 산출물 — 태그 클러스터
└── results.json           # 중간 산출물 — contextTag 추출 결과
```

## 4. PDP에서 구현해야 할 실험 UI

### 실험 목표

> 기존 리뷰 목록 나열 방식 대신, **"고민 Q&A 패널"** 을 PDP에 삽입했을 때  
> 사용자의 구매 확신도가 높아지는지 검증한다.

---

### 컴포넌트 A — 고민 Q&A 패널 (핵심 실험체)

리뷰 섹션 상단 또는 리뷰 탭 진입 시 첫 화면에 노출.

```
┌─────────────────────────────────────────┐
│  💬 구매 전 많이 궁금해하는 것들         │
├─────────────────────────────────────────┤
│                                         │
│  Q. 세안 후부터 메이크업까지             │
│     언제든 사용 가능할까?               │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │ 👤 팡팡99                        │   │
│  │ "화장하기전에는 물론,            │   │
│  │  화장후에 뿌려도 괜찮아요"        │   │
│  │ ⭐⭐⭐⭐⭐  · 리뷰 8건 동의      │   │
│  └─────────────────────────────────┘   │
│                                         │
│  Q. 끈적이지 않고 흡수는 잘 될까?      │
│  Q. 하루종일 촉촉함이 유지될까?        │
│                                         │
│             [리뷰 전체 보기 →]         │
└─────────────────────────────────────────┘
```

**데이터 연결:**
- `concern.question` → Q 텍스트
- `concern.representativeQuote` → 대표 답변 quote
- `concern.reviewIds[0]` → 작성자 프로필 (reviews_200.json에서 reviewId로 lookup)
- `concern.reviewCount` → "리뷰 N건 동의"

---

### 컴포넌트 B — 질문 클릭 시 연관 리뷰 드로어

질문 탭 클릭 → 해당 concern의 `reviewIds` 전체를 리뷰 카드로 나열

```
┌─────────────────────────────────────────┐
│  ← 세안 후부터 메이크업까지             │
│     언제든 사용 가능할까?               │
├─────────────────────────────────────────┤
│                                         │
│  👤 팡팡99  ·  복합성  ·  ⭐⭐⭐⭐⭐  │
│  "화장하기전에는 물론, 화장후에         │
│   뿌려도 전혀 무겁지 않아요..."         │
│                                         │
│  👤 유키나  ·  건성  ·  ⭐⭐⭐⭐⭐    │
│  "스킨케어 마지막 단계에 뿌려요.        │
│   메이크업 전에도 써봤는데 안 밀려요"   │
│                                         │
│  [더보기]                               │
└─────────────────────────────────────────┘
```

**데이터 연결:**
- `concern.reviewIds` → 리뷰 ID 배열
- reviews_200.json에서 `reviewId` 매칭 → 전체 리뷰 카드 렌더링

## 5. 실험 변수 (A/B 테스트 설계)

| | Control | Variant A | Variant B |
|---|---|---|---|
| **UI** | 기존 리뷰 목록 | Q&A 패널 + 리뷰 | Q&A 패널만 (리뷰 숨김) |
| **Q 개수 노출** | - | 전체 | 상위 3개만 |
| **Quote 방식** | - | 짧은 quote | 리뷰 전문 (펼치기) |

## 6. 스킨 코드 → 라벨 변환

**사전은 `data/input/skin_codebook.json` 이 정본이다.** 아래는 그 사본이며, 값이 갈리면 파일이 이긴다.

**출처: PDP DOM 실측 (2026-09-03)** — www.oliveyoung.co.kr PDP 리뷰 탭의 리뷰 위젯(Lit web component,
Shadow DOM)에서 직접 추출. 근거는 코드북 `_meta.evidence`, 화면 캡처는 `docs/evidence/skin_filter_modal_2026-09-03.jpg`.
커버리지 검증: `python crawler/verify_skin_codebook.py` (25,000건 관측 코드 26종 전부 커버, 미지 코드 0).

```
skinType   (단일 선택, 7종)  A01=지성  A02=건성  A03=복합성  A04=민감성
                             A05=약건성  A06=트러블성  A07=중성
skinTone   (단일 선택, 6종)  B01=쿨톤  B02=웜톤  B03=봄웜톤
                             B04=여름쿨톤  B05=가을웜톤  B06=겨울쿨톤
skinTrouble(최대 2개, 13종)  C01=잡티  C02=미백  C03=주름  C04=각질  C05=트러블
                             C06=블랙헤드  C07=피지과다  C08=민감성  C09=모공
                             C10=탄력  C11=붉은기  C12=가려움  C13=다크서클
```

경계 확인: A08 / B07 / C14 이상은 라벨이 없고 코드가 그대로 반환된다 → 도메인은 위 26종으로 닫혀 있다.

> **폐기된 구 표 주의** — 이 문서의 구버전에는 `A01=건성, A02=지성, A04=중성, A05=민감성` 표가 있었고
> 문서 자체가 "코드 체계는 추정값"이라고 적어뒀다. 실측 결과 **A01/A02가 뒤바뀌어 있었고** A04도 틀렸다.
> A05~A07 · B05~B06 · C11~C13 은 표에 아예 없었다. 그 표를 인용한 서술이 있으면 전부 고쳐야 한다.
> 필드명도 `skinConcerns`(구) → `skinTrouble`(현 API)로 바뀌었다.

## 8. 현재 파이프라인 상태

- ✅ 크롤러: 5개 제품 × 200건 수집 완료 (`reviews_200.json`)
- ✅ Step 2 (contextTag 추출): `results.json`
- ✅ Step 3 (태그 병합): `merged_tags.json`
- ✅ Step 4 (질문 생성): `concerns_v2.json`
- ⏳ concerns_v2는 소규모 샘플 기반 — 200건 데이터로 재실행 예정
