## 0. 한 문단 요약

올리브영 리뷰 200건에 대해 **(리뷰 × 주제) 태그**를 만든다. 주제는 정해진 14종이고, 각 태그는
방향(긍정/부정/중립)과 **원문에서 그대로 잘라낸 인용**을 가진다. 이 결과물은 다른 모델의 태깅을
채점하는 **평가 기준**이 되므로, 속도보다 **빠뜨리지 않는 것**이 중요하다.

기존 정답셋(v1)이 이미 있고 **덮어쓰지 않는다.** 새로 만든 것을 v2로 따로 내고, 둘을 대조해
사람이 판정한다.

## 2. 입력 데이터 받기

표본 200건은 `eval/gold/v5_tag_pilot_sample.jsonl` 에 고정돼 있다. 태거에게 줄 형식으로
바꾸는 스크립트가 준비돼 있다.

```bash
# 5건씩 (권장). --chunk 0,1,2,... 으로 40번 돌면 200건 전부
python3 eval/playground_payload.py --chunk 0 --size 5

# 시스템 프롬프트 정본 확인용
python3 eval/playground_payload.py --system
```

> **`--with-gold` 옵션은 쓰지 말 것.** v1 정답을 같이 출력한다 (R2 위반).

입력 형식은 이렇게 생겼다.

```json
[{"reviewId": 123, "content": "리뷰 원문", "rating": 5}]
```

**`content` 를 손대지 말 것.** 원문의 `\r\n` 은 이미 `\n` 으로 접혀 있다
(`pipeline/tag_contract.fold_invisible`). 인용을 대조하는 본문과 태거에게 주는 본문이 같아야
하기 때문이다. 한 글자라도 바꾸면 인용이 전부 탈락한다.

## 3. 사용할 프롬프트

**`eval/gold/regold_prompt_v1.md` 를 시스템 프롬프트로 그대로 쓴다.**

이 프롬프트는 프로덕션 태거 프롬프트(`pipeline/prompts/tag/v1.md`)보다 두껍다. 택소노미·계약·
출력 형식은 완전히 같고, 다른 것은 두 가지다.

1. **14축 각각의 정의를 풀어 썼다** — 특히 `가성비`
2. **14축을 빠짐없이 훑으라고 명시한다**

### 이 차이가 만드는 결과를 알고 있어야 한다

정답셋이 두꺼운 프롬프트로 만들어지면 **재현율의 분모가 커진다.** v1 대비 태그가 늘어날 것이고,
그러면 기존 채점 수치(예: Haiku 재현율 60.5%)와 **직접 비교할 수 없다.** 이건 의도된 것이다 —
정답셋은 "이 프롬프트가 뽑아내는 것"이 아니라 **"리뷰가 실제로 말한 것"**에 가까워야 한다.

**작업 리포트에 이 사실을 반드시 적을 것.** 새 수치를 옛 수치와 나란히 놓지 말 것.

### 알려진 편향 — 숨기지 말고 적을 것

`가성비` 축의 설명("가격 단어가 없어도 성립한다: 용량 대비 소모, 다른 제품과의 비교, 구매 후회…")은
**v1 정답셋에서 이 축이 크게 누락됐다는 관찰 뒤에 쓰였다.** 즉 프롬프트가 이 축을 더 잡도록
의도적으로 기울어 있다. 개념적 정의일 뿐 v1의 특정 인용을 베낀 것은 아니지만, **완전히 독립적인
재작성은 아니다.** 리포트에 그대로 적는다.

## 5. 작업 절차

1. **1패스** — 40청크(5건씩)를 각각 태깅한다
2. **2패스 (필수)** — 각 리뷰에 대해 1패스 결과를 보여주고 되묻는다:
   *"이 리뷰가 말하고 있는데 위 목록에 빠진 축이 있는가? 14축을 다시 확인하라."*
   - 이 단계가 정답셋 품질의 핵심이다. 1패스는 축을 하나 찾고 멈추는 경향이 있다
   - 2패스가 같은 축을 또 내면 R5 위반이므로, 합칠 때 중복을 제거한다
3. **자체 검증** — §7의 명령으로 계약을 통과하는지 확인한다. **실패하면 고쳐서 다시 낸다**
4. **제출** — §6 형식으로 파일을 내고 §8 리포트를 함께 쓴다

## 6. 산출물 형식

**경로: `eval/gold/v5_tags_pilot_gold_v2.jsonl`**

JSONL. 한 줄이 태그 하나다. (리뷰 × aspect) 단위이므로 리뷰 하나가 여러 줄이 될 수 있다.

```json
{"reviewId": 4119503, "aspect": "보습감", "polarity": "negative", "snippet": "속보습은 못 느꼈어요", "skinTypeHint": "A02"}
{"reviewId": 4119503, "aspect": "지속성", "polarity": "negative", "snippet": "금새 날라가는 느낌이에요", "skinTypeHint": "A02"}
```

| 필드 | 타입 | 규칙 |
|---|---|---|
| `reviewId` | int | 표본에 있는 값이어야 한다 |
| `aspect` | str | 14종 중 하나. 한 글자도 바꾸지 않는다 |
| `polarity` | str | `positive` · `negative` · `neutral` |
| `snippet` | str | 원문의 정확한 부분문자열. 40자 이내 |
| `skinTypeHint` | str \| null | `A01`~`A07` 또는 `null` |

태그가 없는 리뷰는 줄이 없다 (빈 배열을 쓰지 않는다).

## 7. 인수 조건 — 이 명령들이 통과해야 한다

```bash
# 1. 계약 검증 + 프로파일. 위반이 하나라도 있으면 여기서 멈춘다
python3 eval/validate_tags.py \
  --tags eval/gold/v5_tags_pilot_gold_v2.jsonl \
  --label gold_v2 --tagger "<사용한 모델 ID>" \
  --out eval/reports/v5_tag_gold_v2.json

# 2. 표본이 안 바뀌었는지 (R1)
python3 pipeline/sample_tag_pilot.py --check

# 3. v1 과 무엇이 달라졌는지 — 사람 판정용 목록
python3 eval/diff_tags.py \
  --old eval/gold/v5_tags_pilot_gold.jsonl \
  --new eval/gold/v5_tags_pilot_gold_v2.jsonl \
  --out eval/reports/gold_v1_v2_diff.md
```

1번이 실패하면 **에러 메시지가 위반한 태그의 인덱스와 사유를 알려준다.** 사유는 다섯 가지다.

| 에러 | 뜻 | 고치는 법 |
|---|---|---|
| `택소노미 밖의 aspect` | 14종에 없는 이름 | 오타이거나 축을 지어냈다 |
| `polarity 는 … 중 하나여야` | 방향 값 오류 | 셋 중 하나로 |
| `같은 리뷰에 aspect 가 두 번` | R5 위반 | 하나만 남기거나 둘 다 버린다 |
| `snippet 이 원문 부분문자열이 아니다 (띄어쓰기가 바뀜)` | 줄바꿈을 공백으로 바꿨거나 지웠다 | 줄바꿈을 넘어가지 말고 한쪽만 잘라낸다 |
| `snippet 이 원문 부분문자열이 아니다 (원문에 없음)` | 글자가 다르다 | 원문을 그대로 복사한다. 오타도 고치지 않는다 |
| `skinTypeHint … 코드북 밖` | 라벨을 썼다 | `A01`~`A07` 코드로 |

## 8. 제출할 리포트에 반드시 들어갈 것

산출물과 함께 짧은 마크다운 리포트를 낸다.

- **사용한 모델 ID와 설정** (effort/thinking, 청크 크기, 온도)
- **1패스 / 2패스 각각의 태그 수** — 2패스가 얼마나 회수했는지
- **계약 위반 건수와 유형** (고치기 전 기준). 0건이면 0건이라고 적는다
- **§3의 편향 고지** — 프롬프트가 `가성비`를 더 잡도록 기울어 있다는 사실
- **§3의 분모 경고** — 새 수치를 v1 기준 수치와 나란히 놓으면 안 된다는 사실
- **판단이 갈렸던 리뷰** — 애매해서 버린 것, 방향을 정하기 어려웠던 것 몇 건

## 9. 제출 후 — 여기서부터는 사람이 한다

`gold_v1_v2_diff.md` 를 사람이 읽고 판정한다. **자동 채택하지 않는다.**

- v2가 **더한** 태그 → v1이 놓친 것인가, v2가 지어낸 것인가
- v2가 **뺀** 태그 → v1이 과했던 것인가, v2가 놓친 것인가
- **방향이 바뀐** 태그 → 어느 쪽이 리뷰를 맞게 읽었나

판정이 끝나야 v2가 정본이 된다. 그 전까지 **v1이 계속 정본**이고, 기존 채점 수치는 v1 기준으로
유효하다.

## 11. 자주 하는 실수

- **오타를 고친다.** 원문이 `발리는`이면 `발리는`으로 쓴다. 실측된 실패 유형이다
- **줄바꿈을 넘어 인용한다.** 원문 `눈시림\n이었는데` 를 `눈시림 이었는데` 로 쓰면 탈락이다
- **축을 하나 찾고 멈춘다.** 놓침의 84%가 이것이다. 리뷰당 14축을 끝까지 훑는다
- **별점으로 방향을 정한다.** 5점 리뷰 안의 불만도 `negative` 다. 실측 불일치가 12.9%다
- **가격 단어가 없으면 `가성비`가 아니라고 본다.** "헤프게 써진다", "날린 돈"도 `가성비`다
- **빈 리뷰를 결과에서 뺀다.** 태그가 없으면 줄이 없을 뿐, 리뷰를 누락시키면 안 된다
