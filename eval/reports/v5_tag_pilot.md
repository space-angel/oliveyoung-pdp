# 태깅 파일럿 (PER-175 선행) — 구독 토큰 정답셋 200건

수치의 1차 근거는 `eval/reports/v5_tag_pilot.json`, 비용은 `eval/reports/v5_tag_cost_estimate.json`.
정답셋 원본은 `eval/gold/v5_tags_pilot_gold.jsonl` — **손으로 만든 것이라 재생성되지 않는다.**
커밋 대상이고, 배치 결과를 채점하는 기준이다.

디렉터리 규칙과 재현이 막히는 지점은 `eval/gold/README.md`.

```bash
python3 pipeline/sample_tag_pilot.py --check          # 표본 재현 (시드 20260904)
python3 eval/validate_tags.py --tags eval/gold/v5_tags_pilot_gold.jsonl \
  --label pilot_gold --out eval/reports/v5_tag_pilot.json
```

## 무엇을 한 건가

Batch API 전수 실행 전에 **구독 토큰으로 200건을 직접 태깅**했다. 태거는 Opus 5이고
배치는 Haiku 4.5로 돌릴 것이므로, 이 결과는 배치의 리허설이 **아니다**. 프롬프트·택소노미·
계약을 검증하고, 배치 결과를 채점할 **정답셋**을 만드는 것이 목적이다.

표본은 평점 층화 + skinType 기재/미기재 반반 + 50제품 분산 (`eval/gold/v5_tag_pilot_meta.json`).
1~2점을 6.8배, 5점을 356배 축소해 뽑았으므로 **표본 비율을 코퍼스 비율로 읽으면 안 된다** —
리포트의 `corpusEstimate`가 가중치로 되돌린 값이다.

| | 표본 | 코퍼스 환산 |
|---|---|---|
| 리뷰 | 200 | 25,000 |
| 태그 | 365 | 51,385 (추정) |
| 리뷰당 태그 | 1.82 | **2.06** |
| 부정 비율 | 43.8% | **14.0%** |

## 결과 1 — 인용 원문성 100%, 단 정규화가 없으면 불가능하다

처음 작성한 태그 50개 중 3개가 부분문자열 판정에 떨어졌다. 원인은 태거가 아니라 **원문의
보이지 않는 문자**였다.

```
25,000건 실측
  U+00A0 등 Zs 공백 변종 포함 리뷰   268건 (1.1%)
  개행이 \r\n 인 리뷰              11,582건 (46.3%)
```

태거에게 주는 본문과 대조하는 본문 양쪽에 같은 접기(`tag_contract.fold_invisible`)를 적용해
해결했다. 접는 것은 보이지 않는 문자뿐이고 글자·띄어쓰기 수는 그대로다 — 재구성·요약은
여전히 탈락한다(`test_tag_contract.py` 8케이스로 고정). **v4의 88.8%에 이 몫이 섞여 있었을
가능성이 높다.**

### 중복 판정(게이트2)에는 같은 정규화가 필요 없다

인용과 중복은 규칙이 다르다. 왜 다른지를 나중에 다시 묻지 않도록 25K에서 재봤다
(`contracts.content_hash` 는 현재 `content.strip()` 후 sha256):

| 해싱 전 정규화 | 중복 그룹 | 초과 표 |
|---|---|---|
| 현재 (strip만) | 587 | 846 |
| 보이지 않는 문자만 접기 | **587** | **846** |
| 공백 전체 제거 (`"".join(split())`) | 621 | 885 |
| 공백 1개로 접기 (`\s+`→`' '`) | 619 | 882 |

**접기의 증가분은 정확히 0이다.** CRLF가 46.3%에 있지만 일관되게 들어가 있어서, 같은 본문인데
줄바꿈만 다른 쌍이 이 스냅샷에 없다. squeeze는 정의에 따라 그룹 32~34개·초과 표 36~39건을
더 잡지만 전체 초과 표 5,611건의 **0.6~0.7%**이고, 그 대가로 "띄어쓰기만 다른 서로 다른
리뷰"를 병합할 위험을 진다.

→ **`contentHash` 규격은 그대로 둔다.** 인용에서 squeeze를 기각한 것과 같은 이유다 — 인용은
재구성을 통과시키면 안 되고, 중복은 이득이 0.7% 미만이다.

두 squeeze 정의의 차이는 접기 여부와 무관하다. 4변형을 25K에 돌려 분리했다 — 접기 후/전이
같은 값이고(A=D, B=C), 갈리는 것은 공백을 **전부 제거**하는지 **하나로 접는지**뿐이다.
전부 제거는 `"좋아요 정말"`과 `"좋아요정말"`을 같게 보는 더 강한 dedup이다.

> 교차 확인: `contentHash` 는 PER-170·171·173 세션(`pipeline/contracts.py`)의 계약이고,
> 위 표는 그 세션과 서로 독립적으로 돌려 A=D·B=C까지 일치를 확인했다. 어느 정의든 판단은 같다.

## 결과 2 — (리뷰 × 주제) 단위가 실제로 필요하다

| 신호 | 값 | 뜻 |
|---|---|---|
| 한 리뷰 안에서 방향이 갈림 | **20.5%** (36/176) | 리뷰 단위 감성이면 이만큼의 방향 정보를 잃는다 |
| 별점과 태그 방향 불일치 | **12.9%** (47/365) | 5점 리뷰의 불만, 1점 리뷰의 칭찬. 오류가 아니라 게이트3이 잡아야 할 것 |

층별로 보면 5점 리뷰 60건에서도 부정 태그가 13개 나왔다. 별점을 방향의 대리값으로 쓰면
이 13개는 전부 긍정으로 뒤집힌다.

## 결과 3 — `skinTypeHint`는 조건축을 늘리지만, 덮어쓰면 안 된다

힌트를 라벨이 아니라 **코드(A01~A07)** 로 받게 해서 조건축과 같은 어휘에 놓았다 (v4가
집계에서 힌트를 잃은 지점).

| | 건수 |
|---|---|
| 본문에서 피부타입을 밝힌 리뷰 | 28 / 200 |
| 그중 `condition.skinType`이 **미기재** → 조건축 순증 | **9** |
| 조건축과 **불일치** | **6** |
| 조건축과 일치 | 13 |

불일치 6건(예: `reviewId 32320525` 프로필 A02 · 본문 "전 복합이긴 한데" → A03)은 프로필
등록값과 이번 리뷰의 자기 진술이 다른 경우다. **자동 우선순위를 정해 덮어쓰지 않는다** —
리포트에 플래그로 남기고 게이트 단계에서 규칙을 정한다.

## 결과 4 — v4 14종 택소노미는 색조에서 구멍이 난다

```
상위 6종이 74.0% 점유
발림감/텍스처 55 · 발색 52 · 보습감 51 · 트러블/자극 48 · 유분/번들거림 33 · 지속성 31
꼬리:  밀착력 22 · 흡수력 15 · 향 10 · 커버력 10 · 광택/윤기 5 · 탄력/탱탱함 3 · 분사력 0
```

- **분사력은 200건에서 0회.** 미스트가 표본에 안 걸렸다는 뜻일 수도 있으나, 전수에서도 희소하면
  N_min을 절대 못 넘는다.
- 태그를 못 붙이고 **침묵한 리뷰가 24건(12%)**. 사유를 세어 보면 **19건은 리뷰가 구체적
  주제를 말하지 않았고**("만족스럽고 조아요, 8번 구매했습니다"), **5건은 택소노미에 칸이
  없었다** — 피부결(`54934222`), 모공(`62195813`·`63219261`), 맛(`62875560`), 용기 파손(`61479701`).
  침묵의 대부분은 정상 동작이지 택소노미 결함이 아니다. 다만 태그를 붙인 리뷰 안에서도
  주름·속눈썹 길이·컬링은 갈 곳이 없어 버려졌다.
- 같은 aspect 안에서 방향이 갈려 **한쪽을 버려야 한 사례**도 있다 (`63358864`: "발색력 좋은"
  positive vs "노란기 있어 아쉬움" negative). 중복 금지 규칙의 비용이고, 실측된 빈도는 낮다.

택소노미는 이번에 바꾸지 않았다 — v4 대비 비교(PER-201)의 축이기 때문이다. **바꾸려면 별도
이슈에서 근거를 대고 바꾼다.**

## 결과 5 — 비용 전제가 틀렸다 (여전히 싸다)

이슈의 비용표는 v4 실측 **리뷰당 1.65클레임**을 깔고 있는데, 파일럿 코퍼스 환산은 **2.06**이다.
출력 토큰이 1.25배가 된다.

| Haiku 4.5 | 표준 | Batch | 캐싱 | 둘 다 |
|---|---|---|---|---|
| 이슈 표 (1.65 전제) | $20.24 | $10.12 | $19.31 | **$9.65** |
| 재계산 (2.06 실측) | $23.86 | $11.93 | $22.58 | **$11.29** |

입력 토큰은 PER-175의 `count_tokens` 실측을 그대로 썼고, 시스템 프롬프트만 v5 프롬프트가
길어진 만큼(829 → 1,139) 문자수 비례로 **추정**했다. **배치 실행 전에 `count_tokens`로
다시 재야 한다** (현재 `.env` 없음 — API 키 미보유).

## 배치 실행 시 고정할 것

1. 프롬프트는 `pipeline/prompts/tag/v1.md` 그대로. 해시가 리포트 `prompt.sha256`에 남는다.
2. 배치 입력은 `tag_contract.tagging_text()`를 통과한 본문. 접기를 안 하면 인용이 깨진다.
3. 결과는 `validate_tags`를 통과해야 한다 — 위반은 태그를 버리는 게 아니라 **실행을 세운다**.
4. 채점 키는 `(reviewId, aspect)` 뿐이다. 정답셋에 `productId` 를 넣지 않았다 — 리뉴얼 세대가
   갈리면(PER-172) 같은 `goodsNo` 의 `productId` 가 날짜로 나뉘어 키가 깨진다.
5. 표본은 `eval/gold/v5_tag_pilot_sample.jsonl` 로 고정돼 있다. 입수 결과가 바뀌어
   `sample_tag_pilot.py --check` 가 실패하면, 표본을 덮어쓰기 전에 정답셋이 무의미해지는지부터 본다.
6. 채점: `python3 eval/validate_tags.py --tags <배치결과> --against eval/gold/v5_tags_pilot_gold.jsonl`
   → (리뷰 × aspect) 단위 precision/recall + polarity 일치율.
7. **전수 25,000건을 태깅한다.** 리센시 컷(2024-09~) 통과분 22,194건만 태깅하면 11.2%,
   **$1.27**을 아낀다 (`$11.29 × 0.112`). 그 대가로 잃는 것이 더 크다:
   - 컷 값(24개월)은 셀 손실 −10으로 정한 값이고 PER-200 커버리지 측정 뒤 조정될 수 있다.
     미리 걸러 태깅하면 **컷을 바꾸는 순간 재태깅**이다.
   - 컷이 "게이트 판정"이 아니라 "입력에서 빠진 것"이 되어 `rejected[]` 회계가 깨진다.
     버린 리뷰가 무슨 aspect를 말했는지 모르면 **재현율을 영영 못 잰다** (PRD §6).

   컷을 되돌릴 수 있게 유지하는 값이 $1.27보다 크다. (PER-172 세션과 교차 확인)
